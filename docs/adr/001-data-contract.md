# ADR 001: Property Data Contract



- Status: Accepted

- Date: 2026-10-03



## Context



The application needs a consistent contract for property and sponsor data generated by AI. The data must be validated before it is displayed, support reliable filtering, and provide matching TypeScript types.



## Decision



JSON Schema is the source of truth for runtime validation. Each property uses a unique property ID and contains one to three local sponsor records with unique sponsor IDs. Amenities use a controlled list of allowed values. AJV validates the JSON records, and `json-schema-to-typescript` generates the matching TypeScript types.



## Alternatives Considered



- Free-text amenities were rejected because spelling differences would make filtering unreliable.

- A separate many-to-many amenities structure was rejected because it adds unnecessary complexity for this small project.

- Manually maintained TypeScript types were rejected because they could become inconsistent with the JSON Schema.



## Consequences



The data is consistent, invalid records fail safely, and TypeScript definitions remain connected to the schema. Adding a new amenity requires updating the controlled list and regenerating the TypeScript file.
